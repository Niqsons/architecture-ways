# architecture-ways

Каталог приёмов проектирования систем, работающих со слабыми моделями:
что сработало, что нет и какой ценой.

| Файл | Что это |
| --- | --- |
| [`ARCHITECTURE.md`](ARCHITECTURE.md) | сам каталог — 63 приёма в девяти группах |
| [`map/dependencies.yaml`](map/dependencies.yaml) | карта зависимостей между приёмами, машиночитаемая |
| [`analysis/`](analysis/) | разборы чужих решений: что взяли, что отвергли |
| [`measurements/`](measurements/) | собственные замеры |

## Как читать оценки

У каждого приёма стоит оценка применимости.

| Оценка | Что означает |
| --- | --- |
| **берём** | применено у себя и работает; подтверждено артефактом — скриптом, прогоном или разобранным инцидентом |
| **кандидат** | идея из чужого проекта или из общих соображений, у себя не применялась |
| **позже**, **осторожно**, **не берём** | по смыслу слов |

Сейчас: 35 «берём», 25 «кандидат», 2 «позже», 1 «осторожно».
Три приёма применены частично и перечислены в `partially_applied`
карты — чтобы «берём» у них не читалось как полное применение.

Приём с наблюдённым отказом ценнее приёма из общих соображений: таких
приёмов семь, а самих отказов восемь — на §6.7 приходится два.

## Пометки источника

**Other** — из разбора другого проекта, **SELF** — собственная
наработка, **PRACT** — общая практика. Конкретный проект указан
в `map/dependencies.yaml` полем `source_projects`.

## Границы

Каталог описывает приёмы, а не продукт. Имена рабочих систем,
внутренние адреса и идентификаторы сюда не попадают — правила
и проверка описаны в [`CLAUDE.md`](CLAUDE.md).
