# Graphify: карта кодовой базы для агента глазами субстрата

**Разобрано:** `graphify` (8e09034), клонирован 2026-09-25. Python,
около 50 тысяч строк только в модулях верхнего уровня пакета, лицензия
Apache-2.0. Прочитаны описания: `ARCHITECTURE.md`, `docs/how-it-works.md`,
`BENCHMARKS.md`, README. Из кода прочитаны:

- нормализация id (`ids.py`), сборка (`build.py`), дедуп сущностей (`dedup.py`);
- промпт и привязка доказательств LLM-прохода (`llm.py`,
  `skill.md`, `skills/*/references/extraction-spec.md`);
- разрешение упоминаний из markdown (`markdown_resolution.py`);
- кеш (`cache.py`), запрос (`serve.py`);
- рабочая память (`ingest.py`, `reflect.py`), межрепозиторные проходы
  (`cross_repo_types.py`, `cross_repo_calls.py`);
- защита от сжатия графа (`export.py`), подсказки хуков (`cli.py`),
  CHANGELOG.

**Повод.** Нужен родственный проект, который закрывает большую часть
потребностей субстрата: если он найдётся, доработать дешевле, чем
строить. Graphify — первый в серии. Мерка, по которой меряются все
кандидаты, — [substrate-needs.md](substrate-needs.md). Вердикт идёт
первым разделом.

**Метод и его граница.** Читались механизмы, отвечающие на вопросы
мерки, а не весь код. Не разбирались: экстракторы отдельных языков
(37 грамматик tree-sitter), экспорт (Obsidian, Neo4j, HTML), панель
PR, транскрипция. Замеры источника не воспроизводились — харнеса
замера в репозитории нет. Подсчёты по CHANGELOG сделаны грепом, они
грубые и так и помечены.

> «§N» — раздел `ARCHITECTURE.md`; «PIPELINE §N» — раздел `PIPELINE.md`
> v3 репозитория `substrate-building`; «Н#» — строка мерки.

## Вердикт

**Как основа для субстрата — нет.** Из десяти несущих строк мерки
закрытых ноль, частично закрытых три, отсутствующих три и четыре —
**против**:

- Н5 — ребро только по дословному якорю;
- Н7 — постоянный машинный id;
- Н9 — реестр производный, петли в него не пишут;
- Н13 — доверие повышает не производитель.

Чтобы доработать, пришлось бы снести LLM-проход по документам, дедуп
по меткам, петлю памяти и схему идентичности. От Graphify остался бы
AST-движок, а субстрат пришлось бы строить рядом. Это уже не доработка.

**Почему расхождение такое сильное.** Задачи разные. Graphify отвечает
агенту на вопрос «куда смотреть» и экономит токены; ошибка ребра стоит
ему лишнего чтения файла. Субстрат отвечает человеку на вопрос «что
с чем связано и где расходится»; ошибка ребра — ложная связь требования
с кодом, которую потом процитируют. Отсюда противоположные решения
при общем лозунге «граф, а не вектор».

**Как донор — да, шесть мест** (раздел «Кандидаты»).

**Как сосед — возможно.** Агентам нужна навигация по коду: вызовы,
импорты, радиус поражения. У субстрата её нет и не планируется.
В режиме `extract --code-only` Graphify ближе всего к здешним
правилам: модели нет, рёбра производные, человеческих решений на его
id не висит, поэтому выводимость id там безвредна. В субстрат его граф
при этом не входит.

## Разрез 1 · Идентичность: id из имени и три производителя

id узла собирается как `{путь_без_расширения}_{сущность}` и проходит
нормализацию: casefold и NFKC до неподвижной точки, затем замена
не-словесных символов (`ids.py`). Шапка модуля называет цену прямо:
три независимых производителя — AST-экстрактор, семантические
субагенты и сборщик — «must agree on node IDs or the graph splits
a single entity into disconnected ghost nodes». Модуль вынесен отдельно
ровно потому, что рецепт копировался между производителями и расходился.
В шапке перечислены номера задач этого класса.

Хуже всех из трёх производителей — модель. Кода она не видит,
а id кодового узла должна воспроизвести сама, по правилу из промпта:
«A doc that *references* an entity mints the ID of the entity's own
file» (`dedup.py`, `_defines_id`). Значит, упоминание в документе даёт
верное ребро, только если модель угадала путь к файлу, где символ
объявлен.

Масштаб по CHANGELOG, грубо: 210 версий и 1033 строки `Fix`. Греп по
ghost, phantom, orphan и node id даёт 138 строк (с шумом). Среди
исправлений — склейка в Go `Run` и `run` в один id: по правилам
видимости языка это разные символы, а общая нормализация делает
casefold. Исправление касается только экстрактора Go («the shared id
normalization is unchanged»), так что для остальных регистрозависимых
языков такая склейка остаётся возможной.

Второе следствие. Единственное непроизводное в Graphify — рабочая
память (разрез 4) — ссылается на id узлов, и при переименовании
«source nodes that no longer exist are dropped» (`reflect.py`).
То есть теряется ровно то, от чего PIPELINE §2.1 защищает связи.

→ **§1.1: наблюдённый отказ источника** к записанному кандидату
и уточнение к абзацу «Почему не к коду». Полное имя символа годится
как id, пока его производит только парсер языка и нормализация
не стирает различий, значимых для языка. Как только то же имя должна
породить модель — или его прогоняют через casefold, — появляется класс
узлов-призраков. Здесь модель id не создаёт, связи заводит CLI
(PIPELINE §2.2), так что класс закрыт по построению. Это также второй
источник строки §10 «Сопоставление объектов по имени».

Чего разрез не даёт: решения для сопоставления при пересборке
(PIPELINE P1). У Graphify переименование — это просто новый узел.

## Разрез 2 · Документ↔код: четыре дороги, одна проверяемая

1. **Упоминание в инлайн-коде markdown** — детерминированно
   (`markdown_resolution.py`). `mod.py::Widget::render` разрешается
   по названному файлу и цепочке владения и даёт `EXTRACTED`. Голое
   `Widget` даёт ребро, только если в корпусе ровно один вызываемый
   символ или тип с такой меткой; квалификаторы `pkg.Widget` обязаны
   совпасть с цепочкой владельцев или путём. Правило записано словами:
   «an ambiguous name is a guess, and a guess is not an edge».
2. **id, угаданный моделью** по правилу из промпта — разрез 1.
3. **`semantically_similar_to`** — ребро `INFERRED` с баллом 0.6–0.95,
   которое ставит модель, в том числе для «a class in code and a concept
   in a paper that describe the same algorithm» (`extraction-spec.md`).
4. **Дедуп некодовых узлов по меткам** (`dedup.py`): MinHash, затем
   Jaro-Winkler с порогом 92 и бонусом +5, если оба узла в одном
   сообществе. Сообщество при этом построено по графу, в котором уже
   есть рёбра модели. Кодовые узлы по меткам не сливаются: это
   запретили после склейки одноимённых символов разных модулей.

Проверяется только первая дорога. Привязка доказательств после
LLM-прохода (`llm.py`, `_bind_node_evidence`) смотрит только узлы типа
`code`, ищет подстроку метки в исходнике без учёта регистра и при
неудаче ставит флаг `unverified`, не удаляя узел. Рёбра не проверяются
вовсе. В выводе запроса метка ребра одна и та же для AST и для модели:
признак происхождения `_origin` — внутреннее поле.

Первая дорога — родня A2 из PIPELINE §4.1 («сверяет, а не находит»):
ищет уже известные имена. Отличие в предмете: A2 ищет якоря —
строковые сущности, а эта дорога ищет символы кода. Форма
`файл::Символ` при этом — **адрес**, а не якорь.

→ **Донор, Н8.** Цитата `файл::Символ` в тексте годится как форма
явного указания связи — замена вызова CLI, записанная автором README
или раздела мастер-спеки. Есть напряжение с инвариантом 3 (якорь
связывает, адрес локализует): адрес вправе устаревать, поэтому такая
связь при неразрешении адреса уходит в «требует пересмотра»,
а не становится ребром по якорю.

Для сравнения: `gsd-graph` из [open-gsd.md](open-gsd.md) записал
в принципы «free prose never becomes a typed edge on its own».
Graphify стоит на противоположном полюсе: проза модели прямо
становится типизированным ребром. Два движка графа — два полюса одной
оси.

## Разрез 3 · Метка доверия: кто её ставит

Метки `EXTRACTED` / `INFERRED` / `AMBIGUOUS`. На LLM-проходе их ставит
модель, и она же выбирает балл `INFERRED` по дискретной шкале
0.95 / 0.85 / 0.75 / 0.65 / 0.55. Причину дискретности источник
записал сам: «the bimodal distribution observed in production (>50% at
0.5, >40% at 0.85+) shows the range guidance is being collapsed to
a binary». Это наблюдённое схлопывание самооценки, вылеченное формой
шкалы. Самооценкой балл от этого быть не перестал.

→ **Второй источник строки §10 «Числовая уверенность поверх
самооценки модели»**, с отказом, который наблюдал сам источник.

Дальше то же в отчёте:

- **раздел «Ambiguous Edges — Review These»** есть, но вердикту некуда
  записаться: следующий прогон покажет тот же список. §5.9 закрыл бы
  именно это;
- **«surprising connections»** сортирует `AMBIGUOUS → INFERRED →
  EXTRACTED` (`analyze.py`): наименее надёжное подаётся главной
  находкой отчёта. Это прямое нарушение инварианта 5 PIPELINE —
  догадка нарисована цветом открытия;
- **«Honesty Rules»** скилла («Never invent an edge. If unsure, use
  AMBIGUOUS») — правило в промпте, а не чекер (§6.7).

## Разрез 4 · Петля ответов: чтение, которое пишет

`save-result` записывает вопрос, ответ, процитированные узлы и исход
(`useful` / `dead_end` / `corrected`) markdown-файлом в
`graphify-out/memory/` (`ingest.py`, `save_query_result`: «so it gets
extracted into the graph on next --update»). Сканер берёт этот каталог
всегда (`detect.py`, «Always include graphify-out/memory/»). Исход
выставляет агент, написавший ответ.

Поверх — `reflect`, и он сделан аккуратно:

- свёртка исходов детерминированная, с полураспадом 30 дней;
- «preferred» — только при двух подтверждениях и больше;
- слой уроков лежит отдельно: «no learning_* fields are ever stamped
  into the graph itself»;
- урок помечается «code changed — re-verify», когда отпечаток кода
  разошёлся, — это §2.10 и §1.2.

Противоречие внутри самого источника: свёрнутые уроки держатся
отдельно от «структурной истины», а сырые ответы, из которых они
свёрнуты, заходят в граф.

Здесь то же место закрыто противоположно. «Цена ошибки чтения — ноль
записи» (PIPELINE §5); петли в реестр не пишут (инвариант 2); журнал
B6 определяет очередь наполнения знания, а не состав графа.

→ **§10, второй источник строки «Переходящие уроки прозой»**,
с уточнением. Детерминированная свёртка самоотчётов с порогом
подтверждения остаётся самоотчётом: два «useful» — это не два
независимых источника, если оба написала модель по одному и тому же
графу. Отдельный вариант — новая строка «ответ читателя возвращается
в корпус индекса», это решение владельца.

## Разрез 5 · Кеш генератов и поколения промпта

Кеш ключуется хешем содержимого, но разный для двух производителей
(`cache.py`):

- **AST-кеш** разложен по версии пакета и схеме ключа; записи чужих
  версий удаляются при первом обращении;
- **кеш LLM-выхода** разложен по отпечатку промпта, и шапка называет
  отказ, от которого это сделано: релиз, сменивший промпт, «keeps
  replaying entries from the older prompt on every unchanged file,
  silently mixing extraction vintages in one graph». Записи старой,
  плоской раскладки ещё отдаются, но их число сообщается человеку.

Здесь для хешей правило есть: смена алгоритма нормализации — смена
версии правил со штатной пересборкой, хеши разных версий
не сравниваются (PIPELINE §2.1). Для генератов модели такого ключа
нет — ни для README-агента, ни для судьи A6, ни для ответов B3. §5.6
требует записать в провенанс модель, промпт и грамматику, но не делает
их ключом повторного использования.

→ **Уточнение §5.6, с отказом источника.** Провенанс генерата —
ещё и ключ его повторного использования. Сменился промпт — генерат
недействителен, а не «старый, но годный». Иначе поколения генератов
смешиваются в одном индексе молча.

## Разрез 6 · Обход: хабы, семена и имя индекса

Запрос (`serve.py`) идёт так:

1. лексический скоринг — IDF и триграммный префильтр;
2. до трёх семян, отсечка по разрыву 20% от лучшего;
3. BFS, по умолчанию глубиной 3;
4. узел со степенью не ниже `max(50, p99)` не раскрывается как
   транзит, если он не семя;
5. бюджет вывода — 2000 токенов.

Две детали держатся на наблюдённых отказах:

- **каждый термин запроса получает своё семя.** Точное совпадение
  нерелевантного термина набирало примерно в тысячу раз больше очков,
  чем подстрочные совпадения нужных, и отсечка по разрыву забирала
  все семена ему;
- **ответ называет граф, из которого получен,** и число узлов в нём.
  Запрос из родительского проекта отвечал по вложенному графу, и
  вывод был «well-formed and confidently wrong».

Здесь B2 — один шаг соседей, глубже — параметр вида, который
оправдывается замером (PIPELINE §5). Хабы режутся при сборке классами
якорей (PIPELINE §2.1), поэтому на одном шаге вопроса нет.

→ **Уточнение §8.2** на случай глубины больше 1: хаб не транзитит;
каждый термин получает своё семя; ответ называет индекс, по которому
получен.

## Разрез 7 · Мультирепо: ребро вместо слияния

Глобальный граф лежит в домашнем каталоге пользователя, id несут
префикс репозитория. Дедуп сущностей между репозиториями запрещён
исключением: одинаковые метки там совпадают случайно.

Два прохода поверх слитого графа:

- **`same_type_as`** (`cross_repo_types.py`) соединяет объявления
  типа с одинаковыми namespace и именем из разных репозиториев —
  ребром, а не слиянием: «Two repos can hold copies of a contract that
  have drifted, and collapsing them would hide that». Замер в шапке:
  на двух сервисах с 1440 и 262 объявленными типами — семь пар, и все
  семь — общие контракты событий шины;
- **межрепозиторные вызовы** (`cross_repo_calls.py`) достраиваются
  только при единственном объявлении типа получателя в другом
  репозитории и на том же языке. Неоднозначное имя ребра не даёт.

С PIPELINE §8 и ADR-009 это совпадение независимое: швы — контурные
якоря схем обмена, копия схемы — свой корпус.

Расхождение — в месте, где живёт граф. У Graphify он личный: N
разработчиков — N глобальных графов, и ровно это ADR-005 отвергает.
Общий HTTP-сервер частично это лечит — один процесс на команду, — но
граф за ним собирает кто-то один, а не планирование контура.

→ **Уточнение §1.3.** Для вида «объявление типа» ключ контурного класса —
namespace плюс имя. Одинаковое объявление в двух репозиториях — ребро,
не слияние.

## Разрез 8 · Корпус подаётся модели как недоверенные данные

Каждый файл перед LLM-проходом заворачивается в
`<untrusted_source path="…" sha256="…">` (`llm.py`, `_wrap_untrusted`).
Шаблонные токены чатов и собственный закрывающий тег обезвреживаются
вставкой невидимого пробела. Системный промпт объявляет содержимое
обёртки данными, а не инструкциями. sha256 позволяет сопоставить
подозрительный узел с точными байтами, которые его породили.
Фрагменты, записанные агентами, до графа проходят проверку размеров,
числа элементов и набора символов id (`semantic_cleanup.py`).

В PIPELINE об инъекциях через корпуса нет ни слова. При этом
постановки, README и документацию пишут и люди, и агенты, а читают
их B3, README-агент и судья.

→ **Новый кандидат, группа 6.** Корпус подаётся модели в обёртке
недоверенных данных, с хешем содержимого. Граница: обёртка снижает
риск, но не гарантирует — модель может подчиниться всё равно, — поэтому
сторожем остаётся проверка выхода (B4, чекер README). Собственного
наблюдённого отказа здесь нет, у источника он тоже только угроза.

## Разрез 9 · Замеры источника

| Замер | Graphify | Соседи |
| --- | --- | --- |
| LOCOMO, n=300, точность ответа | 45.3% (расширение графом) | hybrid RRF 43.3%; только семена, без графа — 42.7% |
| LongMemEval-S, n=50 | 76% | dense RAG 76% |
| код, n=6 вопросов | 82.0% покрытия ключевых фактов | grep и чтение — 70.8% |

Разница между расширением графом и без него — 2–2.6 п.п. на n=300.
Это порядка одной стандартной ошибки доли (~2.9 п.п.); парной
статистики источник не приводит. На LongMemEval — ничья с dense RAG.
**Это независимо совпадает с run-5b** (PIPELINE §4.1): связка «поиск →
граф» идёт вровень с чистым поиском, а ценность графа — в других
вопросах.

Замер при этом сделан не над тем, что лежит в репозитории. Конфигурация
замера включает локальный эмбеддер BGE-m3 и «hybrid retrieval»,
а в пакете эмбеддингов нет: греп по модулям пакета пуст, README
говорит «No embeddings». Харнеса замера (`memory/`, `crosstool/`)
в репозитории нет. Сокращение токенов «71.5x» посчитано против чтения
всех 52 файлов корпуса, то есть против слабого бейзлайна.

Leiden, god nodes. Это и есть роль соседа из вердикта.

## Что совпало независимо

- **Граф, а не вектор; у ребра — метка происхождения.** Здесь это
  статус связи (PIPELINE §2.2).
- **Провенанс и кеш — на хеше содержимого** (§1.2).
- **Неоднозначное имя — не ребро.** Упоминание в документе
  разрешается только при единственном кандидате (PIPELINE §4.1, A2;
  §2.7).
- **Внешний модуль — типизированная заглушка, а не отброшенное ребро**
  (PIPELINE §4.1, AX: терминальные узлы).
- **Между репозиториями — ребро, не слияние** (ADR-009).
- **Воспроизводимость пересборки.** Зерно хеша закреплено ради
  одинаковой кластеризации при ручной пересборке и из хука (§6.6).
- **Устаревание урока вычисляется наблюдением** — по отпечатку кода,
  а не по сроку (§2.10).

## Где здешняя конструкция дальше

**1. Модель не создаёт ни id, ни рёбер.** У Graphify она создаёт
и то и другое — разрезы 1 и 2.

**2. Доверие повышает не производитель** — разрез 3.

**3. Чтение не пишет** — разрез 4.

**4. Отсев виден, а не запрещён числом.** Запрет на сжатие графа
считает только узлы: подмену он пропускает, законное удаление
блокирует и этим приучает к `--force`.

**5. Полнота.** Вопроса «есть в коде, нет в постановке» у Graphify
нет вовсе: он строит карту, а не сверку.

## Где дальше они

**1. Граф код↔код** на ~40 языках, радиус поражения, влияние PR.

**2. Пересборка в такт.** Фоновые git-хуки и merge-драйвер для
`graph.json` работают. Здесь задержка пересборки — метрика без
механизма (PIPELINE §11).

**3. Обход с защитой от хабов и семенем на каждый термин** — разрез 6.

**4. Корпус подаётся модели как недоверенный** — разрез 8.

**5. Генераты инвалидируются по отпечатку промпта** — разрез 5.

## Кандидаты в каталог — на решение

**Внесено в каталог 2026-09-25**, пополнением по итогам серии.
Новый приём — §6.14. Уточнения — §1.1, §1.3, §5.6, §8.2 и строки §10
«Сопоставление объектов по имени», «Числовая уверенность поверх
самооценки модели» и «Переходящие «уроки» между задачами прозой»:
ответ читателя, вернувшийся в корпус, оформлен вторым источником
этой строки, а не новой строкой.

| Кандидат | Куда | Основание |
| --- | --- | --- |
| id из имени годится, пока его производит только парсер языка и нормализация не стирает значимых различий | наблюдённый отказ и уточнение §1.1; второй источник строки §10 «Сопоставление объектов по имени» | шапка `ids.py`; CHANGELOG; потеря уроков при переименовании |

| ответ читателя возвращается в корпус индекса | второй источник строки §10 «Переходящие уроки прозой» или новая строка §10 | `save-result` → `memory/` → граф |
| одинаково объявленный тип в двух репозиториях — ребро, не слияние; ключ — namespace + имя | уточнение §1.3 | `cross_repo_types.py`, замер 7 пар из 1440 × 262 |
| хаб не транзитит, у каждого термина своё семя, ответ называет индекс | уточнение §8.2 | `serve.py`, два отказа источника |
| корпус подаётся модели в обёртке недоверенных данных с хешем | новый приём, группа 6 | `llm.py`; собственного отказа нет |

## Что не берём

- **LLM-проход документов, строящий типизированные рёбра к коду** —
  разрез 2.
- **Нечёткий дедуп сущностей по меткам** с бонусом за общее
  сообщество — сообщество само построено на рёбрах модели.
- **Петлю `save-result` → корпус** — разрез 4.
- **Метку и балл, которые ставит модель**, и сортировку «сомнительное
  первым» в отчёте — разрез 3.
- **Запрет на сжатие графа по числу узлов** вместо видимого отсева.
- **Личный глобальный граф** как общую точку правды контура.
- **Graphify как основу субстрата** — вердикт.
