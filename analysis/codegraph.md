# CodeGraph: индекс кода для агента глазами субстрата

**Разобрано:** `codegraph` (ba3c21e), клонирован 2026-09-25. TypeScript,
около 114 тысяч строк в `src/`, плюс ядро разбора на Rust — около
25 тысяч строк. SQLite с FTS5, лицензия MIT, 31 версия в CHANGELOG.
Прочитаны описания: README, `AGENTS.md`, `TELEMETRY.md`. Из кода прочитаны:

- схема хранилища (`src/db/schema.sql`), id узла
  (`extraction/tree-sitter-helpers.ts`);
- межуровневый синтез рёбер (`resolution/tier-synthesizer.ts`), рёбра
  по значениям (`docs/design/value-reference-edges.md`);
- граница графа (`graph/dynamic-boundary-report.ts`), мёртвый код
  (`graph/dead-code.ts`);
- сохранённые маршруты и их пересопоставление
  (`ui-server/api/trails.ts`, `trail-store.ts`);
- дрейф инкрементального индекса (`docs/benchmarks/index-drift-cg33.md`),
  достаточность ответа (`docs/benchmarks/explore-sufficiency.md`);
- хук на промпт (`bin/codegraph.ts`), тесты синхронизации
  (`__tests__/sync.test.ts`, `ui-trails.test.ts`).

**Повод.** Второй проект серии поиска основы для субстрата; мерка —
[substrate-needs.md](substrate-needs.md), первый разобранный —
[graphify.md](graphify.md). Вердикт идёт первым разделом.

**Метод и его граница.** Читались механизмы, отвечающие на вопросы
мерки, а не весь код. Не разбирались: экстракторы отдельных языков,
резолверы фреймворков по одному, браузерный просмотрщик, установщик.
Замеры источника не воспроизводились, а цифры бенчмарков взяты из его
документов — так и помечено.

> «§N» — раздел `ARCHITECTURE.md`; «PIPELINE §N» — раздел `PIPELINE.md`
> v3 репозитория `substrate-building`; «Н#» — строка мерки.

## Вердикт

**Как основа для субстрата — нет, и не из-за противоречий.** Предмет
CodeGraph — только код. Постановок, документации, связей «требование↔объект»,
отчёта о расхождениях и OpenSpec у него нет вовсе. Из десяти несущих
строк мерки: одна закрыта, пять — частично, три отсутствуют, одна
**против**. Этот ✗ — Н7: id узла — хеш от пути, вида, имени и **номера
строки**. Большую часть того, что называется субстратом, пришлось бы
писать заново рядом с ним.

**Как компонент — первый сильный кандидат серии.** Реестру субстрата
нужны объекты кода уровня символа (PIPELINE §4: «гранулярность
навигации держит реестр»). CodeGraph даёт ровно это:

- объявления с квалифицированными именами на 20+ языках;
- сборка без модели и детерминированная — контрольная пересборка дала
  0 расхождений;
- инкрементальная синхронизация, у которой измерен дрейф и есть
  средство его ловить.

Позиционный id при этом не обязан выходить наружу. У самого CodeGraph
единственный человеческий артефакт — сохранённый маршрут — держится
описанием объекта, а не id, и пересопоставляется после каждой
переиндексации (разрез 1). Ту же схему может взять здешний реестр:
постоянный id — свой, описание объекта — из индекса CodeGraph.

**Цена компонента** — отдельный стек и отдельный контур:

- Node и прекомпилированное ядро на Rust рядом со stdlib-Python
  скриптами субстрата (PIPELINE §9.1);
- интерфейс — внутренняя схема SQLite без контракта; в самой схеме
  упоминается уже девятая миграция;
- телеметрия включена по умолчанию, раз в сутки идёт проверка
  обновлений в сети; для корпоративного контура обе вещи выключаются
  (`DO_NOT_TRACK=1`).

Всё это проверяется не чтением, а пробой на корпусе контура: языки
продукта, объём, доля разрешённых ссылок.

**Как донор — восемь мест** (раздел «Кандидаты»). Три из них несут
наблюдённый отказ источника, и один — первое найденное решение для
половины пробела P1.

## Разрез 1 · Идентичность: позиционный id и ссылка, которая его переживает

id узла — `вид:` плюс первые 32 символа sha256 от
`путь:вид:имя:строка` (`generateNodeId`). Вставка импорта в начало
файла меняет id каждого символа ниже. Для самого индекса это
безвредно: он производный и пересобирается. Опасно для всего, что
ссылается на id снаружи, и источник это знает.

**Рёбра между файлами.** Тест синхронизации правит только докстринг
одной функции — строка соседней сдвигается, её id меняется — и
проверяет, что входящее ребро из другого файла выжило: «A naive
ID-based edge restore would drop callee_two's incoming edge (its node
id changed); the (kind, name) re-resolve preserves it»
(`__tests__/sync.test.ts`). Ребро разрешения несёт ссылку, из которой
возникло (`metadata.refName`). Исчезнувшая цель превращает ребро
обратно в неразрешённую ссылку: она разрешается в той же
синхронизации или паркуется, пока символ не вернётся. Это то же
поведение, что у здешней сироты с автоматическим восстановлением
(PIPELINE §4.3).

**Ссылка человека.** Сохранённый маршрут — путь по символам,
пройденный, чтобы что-то объяснить, — единственное, что просмотрщик
пишет. Шапка `trails.ts` называет задачу прямо: «A trail must survive
a re-index». Шаг маршрута хранится описанием — квалифицированное имя,
вид, файл, строка, — а id остаётся только быстрым путём. При каждом
чтении шаг пересопоставляется с текущим индексом:

| Исход | Условие |
| --- | --- |
| `ok` | записанный id жив **и** называет тот же символ — проверка имени обязательна: id — хеш позиции, и переиспользованный id привёл бы чужой символ |
| `ok` | id не жив, но квалифицированное имя того же вида найдено в том же файле ровно один раз |
| `moved` | имя найдено ровно в одном месте, в другом файле; строка говорит, откуда |
| `ambiguous` | имя носят несколько символов, и одного не выбрать; показана лучшая догадка — с пометкой, что это догадка |
| `missing` | ничто не отвечает на имя: «moved or renamed since this trail was saved» |

«Nothing is silently dropped and nothing is silently guessed». Маршрут
с дырой открывается только самым длинным непрерывным отрезком: сшить
шаг 2 с шагом 4 значило бы нарисовать смежность, которой нет. Тест
правит файлы так, что меняется **каждый** id — символ сдвинут, другой
перенесён в другой файл, третий удалён — и проверяет, что маршрут
открывается и называет судьбу каждого шага.

→ **Донор для PIPELINE P1.** Здешняя формулировка: «объект
сопоставляется по якорям и адресу, неоднозначное сопоставление —
человеку» (PIPELINE §4.3). Здесь это готовый порядок проверок с
исходами. Расхождения два:

- при `ambiguous` источник показывает догадку с пометкой, здесь —
  отдаёт человеку;
- переименование источник не распознаёт: оно становится `missing`.

Так что это закрывает половину P1 — перемещения, но не
переименования.

→ **Уточнение §1.1.** Позиционный id годится как ключ производного
индекса. Для всего, что переживает переиндексацию, ключ — описание
объекта с пересопоставлением и явным исходом. Строка §10
«Сопоставление объектов по имени» при этом не опровергается: имя
здесь — вход сопоставления с проверкой и исходом, а не ключ связи.

## Разрез 2 · Строка на обеих сторонах: межуровневые рёбра

Шапка `tier-synthesizer.ts` описывает три канала и называет основание
ребра: «Each hop is a string on both sides, which is the evidence»:

1. **`http-client`** — литеральный путь в клиентском вызове (`fetch`,
   `axios.post` и родня) → **единственный** узел маршрута `МЕТОД путь`.
   Переменный URL, путь, который не обслуживает ни один маршрут, или
   путь, который обслуживают два маршрута, не дают ничего.
2. **`queue-job`** — `queue.add('job')` в именованной очереди →
   обработчик этой очереди.
3. **`event-bus`** — `emit('user.created')` → `@OnEvent('user.created')`,
   сокеты в обе стороны с пометкой направления.

Каждое ребро — `provenance: 'heuristic'` и несёт `synthesizedBy`,
канал, направление, строку, по которой спарено, и `registeredAt` —
место регистрации обработчика, «so a reader can check the pairing».
Тесты и сгенерированные файлы источниками не бывают: «forty of them
would make the route a hub».

Это здешний якорь (PIPELINE §2.1, §4.1) в чужом коде: путь эндпоинта
и имя топика — те самые виды из Н1, связывание — дословным
совпадением. Узлы маршрутов строятся для 17 фреймворков.

Расхождение одно, и оно принципиальное. Слишком общее событие
отсекается **порогом частоты** — больше шести обработчиков или
отправителей, «too generic to pair». Здесь класс якоря приписан виду
конфигурацией, а не вычисляется частотой (§1.3, PIPELINE §2.1).

Граница канала — только JS/TS (`JS_FILE`) и только внутри одного
индекса.

## Разрез 3 · Происхождение и уверенность: машинный сигнал

У ребра три значения происхождения: `tree-sitter`, `scip`, `heuristic`.
`scip` объявлено, но нигде не производится — импорта SCIP в пакете нет.
Уверенность разрешения ставит не модель, а ветка резолвера, которая
нашла соответствие (`resolution/index.ts`, `name-matcher.ts`). Шкала
идёт от 0.95 — по пути к файлу, по ссылке на функцию — через 0.9 —
по импорту, по квалифицированному имени — до 0.7 у слабейших ветвей
сопоставления по имени. Переадресация через псевдоним ограничена
потолком 0.85. Ниже 0.6 ребро считается догадкой по имени, а не вызовом
(`UNCERTAIN_BELOW`). Синтезированные рёбра показываются в выдаче
отдельным разделом с местом регистрации — читатель проверяет пару
глазами.

Модели в сборке нет вовсе. Шапка отчёта о границе: «no edge is ever
guessed… silence beats a wrong edge».

→ **Второй источник §5.1** (Other к SELF-кандидату): градация
вычисляется из того, **каким путём** найдено соответствие. Оговорка
§5.8 в силе: числа — ранг, а порог 0.6 работает как граница класса,
а не как вероятность.

## Разрез 4 · Дрейф инкрементального индекса

Измерено источником на собственном репозитории
(`docs/benchmarks/index-drift-cg33.md`). Живой индекс, который
поддерживает автосинхронизация, **не сходится** с чистой полной
пересборкой того же дерева:

| | Рёбра |
| --- | --- |
| есть в пересборке, нет в живом | 751 |
| есть в живом, нет в пересборке (устаревшие) | 476 |
| всего расходится | **1 227 — 4.3%** |

**Сумма это прятала.** Строк рёбер 39 845 против 40 122 — безобидные
+0.7%, потому что расхождение двустороннее. Вывод источника: «Any
drift detector must compare edge sets, not totals». Контроль —
пересборка против пересборки — дал 0 расхождений: индексатор
детерминирован, дрейф даёт именно инкремент.

Причин две, обе подтверждены:

1. **Область пересчёта.** Синхронизация пересчитывала ссылки только
   в изменённых файлах. Но новое или удалённое определение имени меняет
   правильный ответ для каждой ссылки на это имя, в том числе в
   нетронутых файлах.
2. **Выбор среди равных.** При неразличимых кандидатах побеждал первый
   по rowid, то есть по порядку, в котором файлы **записывались**.
   Полная сборка пишет в порядке обхода, синхронизация — в порядке
   правок. Одно и то же дерево разрешалось по-разному в зависимости
   от того, как индекс был построен.

Лечение:

- порядок кандидатов задаётся свойством кода — путь и строка, — а не
  порядком записи;
- синхронизация возвращает дельту определений — имена, у которых
  изменилось множество определений, посчитанные **по файлу**, а не
  одним множеством на партию. Рёбра к ним из нетронутых файлов
  переразрешаются.

Итог на 80 коммитах: устаревших рёбер — тех, что индекс продолжает
утверждать, — стало 2 вместо 671. Остаток сознательно оставлен
(общие имена `push`, `join`), и причина названа: сходимость здесь
значила бы научить синхронизацию производить тысячи ложных рёбер.

Отдельное решение: **метрики дрейфа в `status` нет.** Честно её
не посчитать без той самой полной пересборки, которую она советовала бы,
а прокси нарушил бы правило «экран не должен обещать больше, чем знает».

Для здешнего конвейера это прямо на месте. Шаг 8.1 PIPELINE §7.1 —
«инкрементальная пересборка субстрата по diff». Здешний аналог первой
причины: новое вхождение якоря меняет рёбра **всех** корпусов, где этот
якорь есть, а не только изменённого файла. Инвариант 1 проверяется
пересборкой с нуля в эталонном прогоне (PIPELINE §2.5) — источник
показал, чем именно её сравнивать.

→ **Новый кандидат, группа 9.** Инкрементальный индекс сверяется
с полной пересборкой **разностью множеств** рёбер, а не суммами.
Пересчёт при инкременте идёт по ключам, у которых изменилось множество
вхождений, а не по изменённым файлам. Порядок выбора среди равных
задаётся свойством источника.

→ **Второй источник §6.6.** Недетерминизм прячется в порядке — здесь
порядок записи строк, у Graphify зерно хеша.

## Разрез 5 · «Не упомянут» — факт, «мёртв» — вывод

`graph/dead-code.ts`: «`unreferenced` is a fact… `dead` is an
inference on top of that fact, and every step of the inference is
subtractive». Кандидат снимается с каждой причиной, по которой что-то
вне графа может до него дотягиваться: экспортирован, тест или
сгенерированный файл, абстрактный, декорирован, переопределяет,
вендорный каталог, файл, до которого ничто не доходит («a restatement
of "we cannot see how this file is wired"»), есть неразрешённая
ссылка на его имя, есть одноимённый символ, на который ссылаются.
Ответ API перечисляет каждое исключение, снявшее хоть одного
кандидата, с числом, «biggest first».

Граница потока устроена так же (`dynamic-boundary-report.ts`). Когда
поток не соединяется, честный ответ — не «пути нет», а место
динамической диспетчеризации, где статический путь кончается, плюс
короткий список кандидатов по ключу.

Это совпадение с инвариантом 4 (отсеянное видно) и с PIPELINE §2.3
(«отсутствие якоря означает "имя не найдено", а не "этого нет"»)
вплоть до формулировок. Для отчёта A5 здесь готовая форма: исключения
с числом, крупные первыми.

## Разрез 6 · Агент: отказ, инструкция, доставка

Три наблюдения из правил источника (`AGENTS.md`, раздел «do not
regress»):

- **Ошибка учит бросать инструмент.** Один-два ответа `isError: true`
  в начале сессии — и агент перестаёт звать инструмент совсем
  (наблюдение сопровождающих, повторявшееся). Поэтому ожидаемые
  состояния — проект не проиндексирован, символ не найден — отдаются
  **успешным ответом с подсказкой**, а `isError` оставлен для «прекрати
  пытаться»: отказ по безопасности и настоящий сбой. §9.7 уже требует,
  чтобы отказ отличался от сбоя снаружи (нулевой код возврата);
  здесь вторая причина — агент, а не вызывающий скрипт.
- **Инструкции не двигают выбор агента.** Подталкивание через
  инструкции сервера и описания инструментов (три варианта формулировок)
  не воспроизвело эффекта системного промпта и **ухудшило** время
  против базы. Новые инструменты агент выбирает редко; одна сильная
  выдача работает лучше меню.
- **Работает среда.** Хук `UserPromptSubmit` на структурный вопрос
  сам запускает поиск и вставляет выдачу в контекст до того, как агент
  выберет, что делать: «so the agent's reflex grep/read has nothing
  left to find». Любой сбой хука — выход 0 без вывода: хук не имеет
  права сломать промпт.

→ **Второй источник §9.7** (смежное следствие) и **второй источник
строки §10 «Гейт, вызываемый дисциплиной исполнителя»** — с замером
вместо довода: инструкция проиграла, среда выиграла.

---

## Разрез 7 · Полнота моста: половина хуже нуля

«Partial coverage is WORSE than none. Bridging one boundary but not
the next reveals a hop the agent then drills + reads to finish».
Замер на excalidraw: мост только через перерисовку React **поднял**
число чтений файлов до 5–7; лишь закрытие следующего шага (дочерний
компонент JSX) опустило его до 0–1.

Для субстрата это правило про соседей и про B2 (PIPELINE §5):
выдача, которая показывает, что связь есть, но обрывает её посередине,
отправляет читателя восстанавливать остальное — дороже, чем выдача
без этой связи вовсе.

→ **Новый кандидат, группа 8.** Мост через границу выдаётся целиком
или не выдаётся. Граница применимости: правило измерено на поведении
агента и для человека-читателя не проверено.

---

## Разрез 8 · Замеры источника и чего они не меряют

| Замер | Итог |
| --- | --- |
| 7 репозиториев, по одному вопросу, 4 прогона на плечо, медиана | вызовов инструментов −88%, время −53%, токены −62%, стоимость −44%; чтений файлов — 0 на всех семи |
| остаточный контекст в конце многоходовой сессии | **на 80% больше** с CodeGraph (VS Code: 67k против 18k) |
| покрытие межфайловых зависимостей по языкам | 73.8–100% |

Три вещи замера стоят отдельного упоминания:

- **Контрольное плечо было заражено.** Без блокировки агент контрольного
  плеча находил CLI в `PATH` и доходил до CodeGraph через оболочку
  в **26 из 28** прогонов; прежние опубликованные цифры сделаны так.
  Нынешние — с блокировкой CLI в обоих плечах, заражено 0 из 28.
- **Правильность ответа не мерится.** Документ о достаточности говорит
  прямо: «Sufficient is not correct… Answer quality is not measured
  here». Замер показывает, что агент перестал искать, а не что он
  ответил верно.
- **Цена названа.** Меньше обработанных токенов и больше остаточного
  контекста — оба факта верны сразу; источник опубликовал второй сам.

→ **Новый кандидат, группа 9.** Контрольное плечо закрывается по
**всем** каналам доступа к проверяемому инструменту, а не по одному.
Это прямо касается здешних замеров пользы скиллов с плечами.

## Вопрос к PIPELINE: адреса или содержимое

PIPELINE §8 требует от MCP коротких структурных ответов — «список
адресов, не содержимое файлов»: файловый доступ у агента и так есть,
второй запрос — штатное чтение. CodeGraph пришёл к противоположному
и держит это замером. Его цель — чтобы агент **не читал** сам; каждое
чтение — лишний ход и лишние токены. Ответ отдаёт исходный текст
целиком, а правило «никогда не говорить агенту "используй Read"»
закреплено.

Обе стороны неполны:

- замер CodeGraph не мерит правильность ответа и платит остаточным
  контекстом;
- довод PIPELINE не мерен вовсе.

Это не повод менять §8 сейчас. Но строка Н17 мерки держит здешнее
решение как требование, а оно не проверено.

## Что совпало независимо

- **Модели в сборке нет;** молчание лучше ложного ребра (PIPELINE §2.2,
  плотные связи запрещены до субстрата).
- **Межкорпусное ребро — дословная строка на обеих сторонах**
  (PIPELINE §2.1, §4.1).
- **Ребро несёт то, по чему возникло** — строку, канал, место
  регистрации (PIPELINE §4: «у каждого ребра — список якорей»).
- **Исчезнувшая цель — не удаление, а ожидание возврата** (PIPELINE §4.3,
  сироты).
- **«Не найдено» ≠ «нет»; отсеянное перечислено с числом** —
  инвариант 4, PIPELINE §2.3.
- **Экран не обещает больше, чем знает** — отказ от прокси-метрики
  дрейфа против границы, объявленной в выводе `validate` (PIPELINE §7).
- **Две реализации — одна проверка на совпадение.** Ядро на Rust против
  эталонного движка, побайтово — родня контрактных тестов ADR-003.

## Где здешняя конструкция дальше

**1. Предмет шире кода.** Постановки, документация, слой знания —
у CodeGraph их нет по назначению.

**2. Класс якоря — видом, а не частотой.** Порог «больше шести
обработчиков» решает то же, но тихо меняет исход при росте кода.

**3. Неоднозначное сопоставление — человеку.** Маршрут источника при
`ambiguous` показывает догадку; здесь она уходит на вердикт.

## Где дальше они

**1. Объекты кода уровня символа** на 20+ языках, с инкрементом
и измеренным дрейфом.

**2. Сопоставление после переиндексации** с перечислимыми исходами —
половина P1 в работающем коде с тестом.

**3. Проверка инкремента против полной пересборки** разностью множеств.

**4. Доставка контекста агенту средой**, с замером против инструкции.

**5. Чистота замера** — контрольное плечо закрыто по всем каналам.

## Кандидаты в каталог — на решение

В каталог **не внесено**. Состав приёмов меняется в трёх местах
(`WORKFLOW.md`), а кандидаты серии сравниваются вместе.

| Кандидат | Куда | Основание |
| --- | --- | --- |
| ссылка, переживающая переиндексацию, хранится описанием объекта и пересопоставляется с исходом `ok` / `moved` / `ambiguous` / `missing`; id — только быстрый путь с проверкой | уточнение §1.1; вход для PIPELINE P1 | `trails.ts`, тест с изменением всех id |
| инкрементальный индекс сверяется с полной пересборкой разностью множеств; пересчёт — по ключам с изменившимся множеством вхождений | новый приём, группа 9 | отказ источника: 4.3% рёбер, сумма показала +0.7% |
| недетерминизм прячется в порядке — выбор среди равных задаётся свойством источника | второй источник §6.6 | порядок записи строк; у Graphify — зерно хеша |
| градация уверенности — по пути, которым найдено соответствие | второй источник §5.1 | уверенность по виду резолвера, порог 0.6 |
| ожидаемый отказ инструмента агенту — успешный ответ с подсказкой, ошибка — только «прекрати» | второй источник §9.7, смежное следствие | «errors teach abandonment», наблюдение сопровождающих |
| инструкция не двигает выбор агента, среда двигает | второй источник строки §10 «Гейт, вызываемый дисциплиной исполнителя» | три формулировки проиграли; хук на промпт |
| мост через границу выдаётся целиком или не выдаётся | новый приём, группа 8 | отказ источника: 5–7 чтений при половинном мосте, 0–1 при целом |
| контрольное плечо закрывается по всем каналам доступа к инструменту | новый приём, группа 9 | отказ источника: 26 из 28 контрольных прогонов заражены |

## Что не берём

- **Позиционный id** как ключ чего-либо, что переживает переиндексацию, —
  разрез 1.
- **Порог частоты вместо класса вида** для отсечения общих имён —
  разрез 2.
- **Разрешение по имени с выбором кандидата** как основание связи:
  для навигации агента годится, для связи «требование↔объект» — нет.
- **Телеметрию и проверку обновлений по умолчанию** в корпоративном
  контуре — выключаются при установке.
- **CodeGraph как основу субстрата** — вердикт.
