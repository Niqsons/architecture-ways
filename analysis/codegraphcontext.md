# CodeGraphContext: граф кода в сменных графовых СУБД глазами субстрата

**Разобрано:** `codegraphcontext` (a864a9f), клонирован 2026-09-25.
Python, около 57 тысяч строк в пакете, версия 0.6.13, статус
«Alpha», лицензия MIT, 182 файла тестов. Хранилище — на выбор:
FalkorDB Lite, Kùzu, LadybugDB, FalkorDB удалённый, Neo4j или Nornic.
Прочитаны описания: README, три отчёта самопроверки в корне
(`CGC_CALL_GRAPH_AUDIT_REPORT.md`, `CGC_E2E_BUG_REPORT.md`,
`CGC_GRAPH_INCONSISTENCIES.md`). Из кода прочитаны:

- ярусы разрешения вызовов (`tools/indexing/resolution/calls.py`),
  повторное разрешение с эмбеддингами (`post_resolution.py`,
  `vector_resolver.py`, `embeddings.py`);
- ключи слияния узлов и запись связей (`tools/indexing/persistence/writer.py`,
  `schema_contract.py`);
- граф источников данных и сборки (`writer.py`, `tools/datasources/`);
- ограда «только чтение» (`utils/cypher_readonly.py`,
  `tools/handlers/query_handlers.py`, обёртки бэкендов в `core/`);
- инкрементальный наблюдатель (`core/watcher.py`), бандлы
  (`core/cgc_bundle.py`), запросы (`tools/code_finder.py`);
- тесты эталонов и паритета бэкендов
  (`tests/integration/test_parser_goldens.py`,
  `tests/e2e/test_verify_databases_parity.py`).

**Повод.** Третий проект серии поиска основы для субстрата; мерка —
[substrate-needs.md](substrate-needs.md), предыдущие —
[graphify.md](graphify.md), [codegraph.md](codegraph.md).

**Метод и его граница.** Читались механизмы, отвечающие на вопросы
мерки, а не весь код. Не разбирались: парсеры отдельных языков,
визуализация, сайт, мастер установки, симулятор архитектурных
изменений. Три дефекта найдены **чтением кода и не воспроизводились** —
они так и помечены. Отчёты самопроверки датированы июнем 2026 года;
что из перечисленного в них закрыто к разобранному коммиту, сплошь
не сверялось.

> «§N» — раздел `ARCHITECTURE.md`; «PIPELINE §N» — раздел `PIPELINE.md`
> v3 репозитория `substrate-building`; «Н#» — строка мерки.

## Вердикт

**Как основа — нет.** Предмет — только код, как у CodeGraph. Из десяти
несущих строк мерки: закрытых ноль, частично — пять, отсутствуют
четыре, **против** — одна. Это Н7: узел кода сливается по ключу
«имя, **абсолютный** путь, строка, номер вхождения».

**Как компонент — слабее CodeGraph, но по другой причине, чем
Graphify.** Два довода за:

- **стек — Python**, как у скриптов субстрата;
- **охват JVM-экосистемы**, которого нет у двух прежних: модули
  Maven и Gradle с внешними библиотеками, эндпоинты и бины Spring,
  таблицы из JPA, MyBatis и производных запросов Spring Data.

Против — дисциплина, и на ней держатся три главных разреза разбора.
Метки уверенности теряются при чтении. Семантика записи на разных
бэкендах расходится. Версия библиотеки стирается последней записью.
Если в корпусе контура много JVM-сборки и ORM, сравнение
с CodeGraph в роли компонента надо делать пробой, а не чтением.

**Как донор — главное, что есть в разборе.** Шесть бэкендов за одним
интерфейсом — ровно та конструкция, которую ADR-003 планирует для
субстрата: одна файловая реализация и сервис позже, за контрактом
из четырёх операций. У источника она уже прожита, и **каждый
наблюдённый отказ приходится на шов между реализациями**. Это
готовый список того, что обязаны ловить здешние контрактные тесты
(разрез 3).

## Разрез 1 · Уверенность: записана честно, прочитана вслепую

Разрешение вызова проходит девять ярусов, у каждого уверенность
задана в коде (`calls.py`, `_TIER_CONFIDENCE`):

| Ярус | Основание | Уверенность | Метка |
| --- | --- | --- | --- |
| 1 | явный `this` / `self` / `super` | 1.00 | `EXTRACTED` |
| 2 | локальная функция или класс того же файла | 0.95 | `EXTRACTED` |
| 3–4 | выведенный тип получателя + импорт / короткое имя | 0.88 / 0.72 | `INFERRED` |
| 5–6 | уникальное короткое имя; квалифицированный импорт | 0.90 / 0.85 | `EXTRACTED` |
| 7 | совпадение подстроки пути | 0.70 | `INFERRED` |
| 8 | **первый по алфавиту** из нескольких кандидатов | 0.25 | `AMBIGUOUS` |
| 9 | запасной вариант в том же файле для неразрешённого `obj.method()` | 0.08 | `AMBIGUOUS` |

При записи всё сделано честно. Метка — машинная, по ярусу, а не
самооценка модели. Модели в сборке нет. Для эвристических вызовов
есть отдельный тип ребра `HEURISTIC_CALLS`. Отчёт `generate_report`
предлагает запрос «CALLS edges with low confidence (potential
mis-resolutions)».

При чтении честность теряется. Штатный «кто вызывает»
(`code_finder.py`, `who_calls_function`) идёт по
`[:CALLS|HEURISTIC_CALLS]` и не возвращает ни уверенности, ни метки,
ни яруса. Ребро «первый по алфавиту из нескольких» выдаётся рядом
с `self.method()` без различия. Если по имени **и пути** не нашлось
ничего, запрос молча повторяется **без пути** и возвращает вызывающих
любой одноимённой функции.

→ **Второй источник §4.9.** Тихий переход к умолчанию здесь принимает
вид тихого расширения области запроса: ответ есть, но он про другой
объект, и признака этого в ответе нет. Разделение, сделанное при
записи, ничего не стоит, если читатель его не видит, — это
инвариант 5 PIPELINE с другой стороны.

→ **Второй источник §5.1** — градация по пути разрешения, как
у CodeGraph. Здесь добавляется деталь, которую §5.8 предсказывает:
шкала не монотонна по ярусам (ярус 5 — 0.90, ярус 3 — 0.88), то есть
число — ранг внутри семейства, а не вероятность.

## Разрез 2 · Плотная близость решает структурное ребро

При включённых `ENABLE_INHERIT_RESOLVE` и `ENABLE_VECTOR_RESOLVE`
(по умолчанию оба выключены) повторное разрешение берёт рёбра ярусов
8–9 и пробует сузить кандидатов (`post_resolution.py`):

1. кандидат один на весь репозиторий — он и берётся (ярус 10, 0.78);
2. несколько — предпочитаются те, чей класс что-то наследует:
   «prefer polymorphic implementations over utility helpers»;
3. всё ещё несколько — выбирает **близость эмбеддингов** функций
   (ярус 11, 0.82; порог сходства 0.75, эмбеддинги локальной модели
   или платного API).

Чтением найдено, не воспроизведено. Запись заменяет старое ребро
новым `CALLS` — не `HEURISTIC_CALLS` — с `resolution_method:
'inheritance'`, прописанным жёстко, **и при выборе эмбеддингом тоже**.
`confidence_label` при этом не выставляется. Догадке по близости
присвоено 0.82, а структурной эвристике по наследованию — 0.78:
плотный сигнал оценён выше структурного.

→ **Второй источник строки §10 «Векторный поиск как замена
структуре»**, в более острой форме. Близость здесь не дополняет
выдачу, а решает, какое структурное ребро существует, и записывает его
типом доказательства. PIPELINE запрещает ровно это: плотные связи —
после субстрата и отдельным типом (PIPELINE §2.2).

## Разрез 3 · Шесть хранилищ за одним интерфейсом: отказы на швах

Бэкенды спрятаны за обёрткой в форме драйвера Neo4j: `session()`,
`run()`. Контракт графа — модуль `schema_contract.py` с метками, типами
рёбер и ключами слияния: «documentation + test hooks only». Паритет
проверяет e2e-тест, который индексирует один проект в каждый бэкенд.
Это ближайшая из разобранных конструкций к ADR-003 — и у неё
наблюдены четыре отказа, все на швах:

| Отказ | Где видно | Что пропустила проверка |
| --- | --- | --- |
| **разная семантика записи**: на Neo4j и Nornic писатель делает `CREATE`, на FalkorDB и Kùzu — `MERGE`; дубли `CALLS` множились при каждом сохранении, но только на первых двух | комментарий в `watcher.py` | паритет считал **узлы** (482 = 482 = 482); рёбра в отчёте помечены «inferred from shared indexing pipeline» — выведены, а не посчитаны |
| **гарантия «только чтение» не у всех**: сессия открывается в режиме READ (`default_access_mode`, `GRAPH.RO_QUERY`) только для Neo4j и FalkorDB; обёртка Kùzu и Ladybug «accepts and ignores Neo4j-specific kwargs» | `query_handlers.py`, `database_embedded_kuzu.py` | на Kùzu — умолчании для Windows — остаётся один текстовый денилист |
| **текстовая ограда обходилась**: кавычка в комментарии спаривалась с кавычкой литерала, и `DELETE` между ними исчезал из проверки | шапка `cypher_readonly.py` | ограда — разбор языка запросов своими регулярками |
| **удаление оставляет сирот**: после `cgc delete` в графе 9 узлов из 83 — параметры и переменные без пути | `CGC_E2E_BUG_REPORT.md`, BUG-005 | удаление идёт по пути, а у этих узлов пути нет |

Ограда «только чтение» устроена слоями, и источник это пишет прямо:
регулярка на всех бэкендах плюс READ-сессия там, где СУБД умеет.
Разумно. Но слой, который держит сама СУБД, отсутствует ровно на
умолчании одной из платформ, и об этом знает только тот, кто читал
обёртку.

→ **Для здешнего ADR-003 — готовый перечень.** Контрактные тесты
субстрата обязаны включать:

- повторную запись одного и того же — идемпотентность на каждой
  реализации;
- сравнение **множеств рёбер**, а не числа узлов — CodeGraph пришёл
  к тому же с другой стороны;
- отказ, который должна дать сама реализация, а не обёртка;
- удаление с проверкой, что не осталось сирот.

→ **Второй источник §6.9.** «Гарантия, которую даёт не всякий
поставщик, — не гарантия, а просьба» — здесь поставщики не модели,
а хранилища, и расхождение проявилось дважды: запись и режим чтения.

→ **Второй источник §6.10.** Ограда, написанная разбором текста
по представлению о языке запросов, обходилась. Средство среды —
транзакция только на чтение — надёжнее, но проверять его наличие
надо на каждой реализации.

## Разрез 4 · Версия на узле: разнобой стирается последней записью

Граф сборки строит модули Maven и Gradle, связи между ними и внешние
библиотеки (`writer.py`). Библиотека сливается по `group_id` +
`artifact_id`, а версия пишется **на узел** (`SET lib.version =
row.version`). Если два модуля тянут разные версии одной библиотеки,
узел один, и версия на нём — последняя записанная. Ребро
`USES_LIBRARY` несёт только `scope`. Найдено чтением, не
воспроизведено.

Здесь это место — AX (PIPELINE §4.1): «расхождение версий одной
библиотеки по контуру — детерминированная строка отчёта». У источника
та же модель данных делает это расхождение невидимым по построению.

Граф источников данных устроен похоже. Таблица сливается **по имени**
(`MERGE (tbl:DbTable {name: …})`), без базы и схемы. При отсутствии
сведений `datasource_name` проставляется строкой `'mysql'`. Две базы
с таблицей `users` дают один узел — то самое «связал всё со всем через
общеупотребимое имя», от которого классы якорей защищают (§1.3,
PIPELINE §2.1). Тоже найдено чтением.

→ **Новый кандидат, группа 4.** Атрибут, который различается у разных
потребителей общего узла, хранится на ребре, а не на узле. Иначе
расхождение, ради которого его стоило бы хранить, стирает последняя
запись.

→ **§1.3, пример от противного** — имя таблицы без области как ключ
слияния.

## Разрез 5 · Эталоны: круговой гейт и его лечение

Собственный отчёт источника (`CGC_GRAPH_INCONSISTENCIES.md`,
позиция 78) называет отказ: «Circular perfection gate (export vs itself)
— Misleading 21/21 PASS». Эталон сняли выгрузкой с индексатора
и сверяли индексатор с ним же. Там же, позиции 79–81:

- два отчёта дают противоречащие числа — средняя точность `CALLS`
  84.6% против «идеальных» 100%;
- эталон, правленый руками, на диске не совпадает со своими
  метаданными (563/796 против 482/621 в `metadata.json`);
- исправление, проверенное на локальной установке, не попало
  в опубликованный пакет. E2e-отчёт это подтверждает: «Several PyPI
  bugs appear fixed in the working tree but not yet released».

Лечение в нынешнем тесте эталонов (`test_parser_goldens.py`): эталонов
**два**. «What I Wanted» (`nodes.jsonl`) — цель, выправленная по
спецификации. «What We Have» (`nodes_have.jsonl`) — снимок для
регрессии, который перезаписывается флагом `--update-goldens`.
Регрессия меряется по снимку, прогресс — по цели. Снимок, снятый
с проверяемой системы, честно назван снимком и за цель себя
не выдаёт.

Перед сравнением стоит отдельная проверка. Индексация может завершиться
с кодом 0 и оставить граф **пустым**: хранилище поднимается
в подпроцессе и под нагрузкой не успевает. Тогда дифф показал бы все
узлы пропавшими, и это «looks exactly like a parser regression but is
actually an infrastructure failure». Пустой граф отсекается до диффа
и при обновлении эталонов тоже: «bootstrapping a golden from an empty
graph would be worse than failing».

→ **Новый кандидат, группа 9.** Эталон, снятый с проверяемой системы, —
снимок регрессии, а не цель: цель выводится из спецификации
и хранится отдельно. Отказ источника: 21 из 21 зелёных.

→ **Второй источник §4.10.** «Не отработало» и «отработало — пусто» —
разные исходы: пустой граф при коде 0 — сбой среды, а не находка.

→ **Кандидат, группа 9.** Проверка идёт по артефакту, который получает
потребитель, — опубликованному пакету, а не рабочему дереву. Отказ
источника: исправления ждали выпуска, пока пользователи ставили
сломанное.

## Разрез 6 · Живые источники за границей git

Граф источников данных подключается к живым MySQL, Cassandra и Redis
и собирает таблицы, колонки и шаблоны ключей
(`tools/datasources/`). Для Redis «схема» — это обход ключей командой
`SCAN` и свёртка числовых и UUID-сегментов в `*`. Связи «класс →
таблица» и «метод → таблица» строятся по ORM-разметке, XML MyBatis
и именам производных запросов Spring Data.

Со здешней стороны ценна половина. Связь кода с хранилищем по имени
таблицы — это якорь вида «таблица», и он годится (с областью, см.
разрез 4). Сбор схемы из живой базы противоречит ADR-009: база знаний
кончается на границе git, внешнее видно, только когда отражено в git —
миграциями, копией схемы. Индекс, в который вошло живое состояние,
нельзя пересобрать из источников, а это инвариант 1.

→ **Не брать как есть.** Брать извлечение имён таблиц из кода и из
файлов схемы в git.

## Что совпало независимо

- **Метка уверенности — по пути разрешения, а не по самооценке**
  (§5.1) — у CodeGraph и здесь, противоположно Graphify.
- **Эвристика — отдельным типом ребра** (`HEURISTIC_CALLS`) — родня
  здешнему «догадка не рисуется цветом доказательства»; расходится
  только чтение.
- **Слоистая ограда с названной асимметрией ошибок.** «A false
  negative here is a write slipping through a read-only gate while
  a false positive is merely an inconvenience» — неоднозначное
  отвергается.
- **Пустой результат при коде 0 — сбой, а не находка** (§4.10).
- **Бандл как недоверенный вход.** Метки и типы рёбер из бандла
  попадают в текст запроса, поэтому проверяются как исполняемый
  Cypher; пути — против выхода из каталога (Zip Slip).

## Что не берём

- **Идентичность с абсолютным путём** — разрез 1 мерки, Н7.
- **Выбор «первого по алфавиту»** из нескольких кандидатов как ребро.
- **Плотную близость как тай-брейк** структурного ребра — разрез 2.
- **Версию и имя таблицы как ключи без области** — разрез 4.
- **Сбор схемы из живых баз** в индекс, который должен
  пересобираться из git, — разрез 6.
- **CodeGraphContext как основу субстрата** — вердикт.
